# Mayushi

Mayushi is a **secure-by-design reference implementation of an enterprise AI customer-support platform**. It shows how a mid-size company can ship an agentic AI feature (SSO, microservices, a RAG knowledge base, an LLM agent calling business tools through an MCP server, long-term memory and observability) with security controls designed in from the start.

Each significant control is traceable to a threat and a standard (OWASP Top 10:2025, OWASP Top 10 for LLM Applications 2025, OWASP Top 10 for Agentic Applications 2026, OWASP ASVS 5.0) and is proved by an automated test. See [docs/security/controls.md](docs/security/controls.md).

**Product story:** *Northwind Parcel Co.*, a fictional UK logistics firm, runs **Mayu**, an AI support assistant. Customers chat with Mayu about orders, returns and refunds. Staff upload knowledge-base documents, review conversations and run analytics. Two business tenants, `northwind-retail` and `northwind-b2b`, share the platform.

All data is synthetic. The stack is intended for local use and binds only to `127.0.0.1`.

## Quick start

Requirements: Docker Engine with Compose v2, GNU Make, Python 3.

```bash
make bootstrap   # create .env and generate all credentials (never overwrites existing ones)
make up          # build, start the stack and wait for health checks
make seed        # migrations, deterministic demo data, Keycloak settings
make ps          # show service status
make down        # stop
make reset       # wipe volumes, restart and reseed
```

Run `make help` for all targets.

| Service | URL |
|---|---|
| API gateway | http://localhost:8000 |
| Keycloak (identity) | http://localhost:8080 |
| Mailpit (captured email) | http://localhost:8025 |
| PostgreSQL | `localhost:5432` |

```bash

make typecheck         # mypy --strict
make test              # unit tests, including static security tests
make test-integration  # live tests against the running stack (login, DB roles, Keycloak)
```
